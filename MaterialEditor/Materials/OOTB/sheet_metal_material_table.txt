###############################################################################################  
# This is a sample sheet metal material standards file. The main purpose of the file is to  
# describe how to set material parameters so that it can be read successfully by the NX Sheet  
# Metal Application. The file uses comma , as a delimiter and can be stored edited with a
# spreadsheet application.  File extension of .txt and .csv are valid.
#
# Following keywords are recognised by NX Sheet metal and should be used to used to
# define data that can be used by the features.
# THICKNESS
# BEND_RADIUS
# LENGTH
# ANGLE
# NEUTRAL_FACTOR
# JOGGLE_DEPTH
# JOGGLE_RADIUS
# JOGGLE_LENGTH
# RELIEF_WIDTH
# RELIEF_DEPTH
# PHYSICAL_MATERIAL_NAME
#
# The sheet metal standards file is divided into 11 functional blocks.
#
##BLOCK1## NEW
#
# A new block from NX12 that determines the version of each table in the standards file. This will
# provide a clear upgrade path for future format changes to the file.
# It is important that the version numbers are not edited.  The valid values for this release are:
# Standards File VERSION = 1
# Material Table VERSION = 1
# Bend Tool ID Standards Table VERSION = 1
# Tool Selection Tables VERSION = 1
# Formula VERSION = 0 (eg Joggle, Runout)
# Neutral Factor Bend Table VERSION = 1
# Bend Allowance Table VERSION = 1
# Bend Deduction Table VERSION = 1
# Feature Table VERSION = 0 (eg Lightening Cutout)
#
##BLOCK2##
#
# Contains the units of the parameters in the standards file. It can be metric
# or english. A table cannot have more than one unit.  From NX12, two standards files can be used, one
# for each unit of measure.
#
##BLOCK3## NEW
#
# A new block from NX12 that determines how the standards file interprets the bend angles.
# It can be either INSIDE or OUTSIDE.  If INSIDE, the angle created between the webs will be
# used in the bend and tool tables. If OUTSIDE, the angle as entered on the dialog will be used.
# Once set, all tables in the file will use the same method.
#
##BLOCK4##
#
# Contains parameters used as arguments to tables and formulas that are not defined in this file
# but must be provided by the feature.
# E.g.
# PARAMETERS
# FEATURE,JOGGLE_DEPTH
# FEATURE,ANGLE
# EXPRESSION,BAF
# END_OF_PARAMETERS
#
# The type FEATURE means that the string will be substituted by a value provided
# by the API that processes the table.  
# For example FEATURE JOGGLE_DEPTH means that the string JOGGLE_DEPTH will be substituted 
# by a value before it is used. 
# 
# The type EXPRESSION means that the string should correspond to an expression in the 
# part file.  
#
##BLOCK5##
#
# Contains the actual materials table
# MATERIAL_TABLE  
#

# 
# The first row contains the names of the columns. The names should be one word only. 
# Users can also use the keywords to define values for parameters that are recognised 
# by NX, for e.g. THICKNESS, BEND_RADIUS and so on.
# 
# The second row decides the columns properties:  
# unique    - There must be one column with this identifier. This column should contain unique  
#             names of the material.  
# show      - These columns will be used for filtering data through UI when selecting a material
# hide      - The values of these columns will be stored but will not be used for filtering data
# attribute - These columns contain values that are written back to NX as part attributes for use
#             in, for example, PMI and drawings
# 
# A table entry can be a value, string, a pointer to another table or a pointer to a formula.
# pointer to tables and formulas begin with @, for example @JOGGLE_LENGTH_FORMULA_1
#

#
# A separate table is required for each punch and die combination that produce unique output
# 
# Following the name and a number of comment rows, the first row is the input parameters
# the second row is the material thickness.  Two columns are required to return the bend radius and
# neutral factor/bend allowance/bend deduction in the following table
# The first column lists the bend angles. Intermediate values are interpolated.
#
##BLOCK8##
#
# Contains secondary tables pointed to by values in the material table. 
# A secondary table can have 1,2 or 3 input parameters.,
# 
# Example of table with 1 parameter: 
# TABLE 
# NAME,BEND_RADIUS_TABLE_1,
# INPUTS,THICKNESS,
# 1.6,3.2,
# 1.7,3.2,
# 1.8,3.8,
# 1.9,4.2,
# END_OF_TABLE 
# 
# First row of the table contains a unique name of the table.  
# The second row contains the input arguments. The possible value of the input  
# arguments are defined in the first column. The API that reads this table will provide  
# the thickness value as input.  
#  
# Example of table with 2 parameters:  
# TABLE  
# NAME,JOGGLE_LENGTH_TABLE1  
# INPUTS,THICKNESS,JOGGLE_DEPTH  
# THICKNESS,3,4,4.5,5
# 1.6,5,5,6,7
# 1.8,5.5,5.7,6.5,7.4
# 2.0,5.5,5.8,6.6,7.4
# END_OF_TABLE  
#  
# The first parameter defines the values in the first column. The second parameter defines the  
# value in the first row. The value in the first column of the first row can be null or any string.  
# It is not used in a table with two parameters.  
#  
##BLOCK9##
#
# Contains formulas that are used to generate expressions in NX.,
# FORMULA,
# NAME, JOGGLE_LENGTH_FORMULA1 
# INPUTS,JOGGLE_DEPTH,THICKNESS,JOGGLE_RADIUS
# sqrt( 2*JOGGLE_DEPTH*(2*JOGGLE_RADIUS + THICKNESS) - pow(JOGGLE_DEPTH,2) ) 
# END_OF_FORMULA 
#  
# The first row contains a unique formula name. The second row contains the list of 
# input parameters to the formula. The parameters must be either keywords or same as one 
# of the columns of the material table. 
# The third row contains an expression that will be recreated in NX with the parameters 
# substituted with actual values. 
#
##BLOCK10## NEW
#
# Contains bend tables defined for neutral factor, bend allowance and bend deduction 
#
# Example of bend table with neutral factor:
#
#NF_BEND_TABLE
#VERSION,1
#INPUTS,ANGLE,RADIUS
#PAGE
#1.5,1,1.2,1.6,2,2.5
#45,0.35,0.44,0.58,0.69,0.81
#90,0.45,0.54,0.68,0.79,0.91
#135,0.55,0.64,0.78,0.89,1
#END_OF_PAGE
#PAGE
#2,1,1.2,1.6,2,2.5
#45,0.2,0.29,0.44,0.55,0.66
#90,0.3,0.39,0.54,0.65,0.76
#135,0.4,0.49,0.64,0.75,0.86
#END_OF_PAGE
#PAGE
#3,1,1.2,1.6,2,2.5
#45,0,0.09,0.24,0.35,0.46
#90,0.1,0.19,0.34,0.45,0.56
#135,0.2,0.29,0.44,0.55,0.66
#END_OF_PAGE
#END_OF_NF_BEND_TABLE
#
# The tables have three input parameters, thickness, angle and bend radius
# A separate page is created for each thickness value
# The angle is provided in the first column and the bend radius in the first row
# The neutral factor is the output.
# For example PAGE 1 contains the thickness of 1.5, for a bend angle of 90 degrees and a
# bend radius of 2.0, the neutral factor equals 0.79
#
##BLOCK11##
#  
# Contains the standards values specific to a feature. Currently, only Lightening Cutout has
# support for a feature table. The feature table can be thought of as a combination of material
# table and a data table.
# The first row contains a unique table name. The second row contains the names of
# feature parameters. The third row contains the type of column. For feature tables
# only two types are supported, i.e. unique and show. The unique column defines the
# names of each set of feature data. All the other columns contain data values.
#
#
